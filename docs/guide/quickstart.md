# 第一次用：先和团队聊一件事

**已有部署的话，直接从这里开始。** 打开工作台，在「想和团队一起做什么？」下面写一个还没完全想清楚的想法，例如「我想做个提醒大家跟进的小工具」。点 **和负责人聊聊**。这只启动需求讨论，不会直接安排开发。

1. **回答真正的问题。** 负责人会提出会影响方案的问题。在对话底部写下你的回答，例如「只提醒我自己，每天下午看一次清单，不要发群消息」。其他成员在工作中遇到需要你决定的问题，也会出现在这里。回复问题不会批准开发。
2. **先看方案。** 团队会提交其理解的范围和验收方式。方向不对，点 **我想改一改** 并说明原因；认可了再点 **同意方案，开始制作**。
3. **工作期间继续说话。** 在 **成员与议题** 找具体成员私聊，或邀请已有的两位合适成员讨论同一个问题。对话里可以看到提问、答复和交付；不用读内部数据。**工作进度** 显示目前进行到哪一步。
4. **看结果，再决定。** 独立检查通过后，仍由你决定要不要接受交付。开发节点会修改当前项目，所以第一次体验请在练习目录里进行。

## 从源码在另一台机器安装

需要 Linux、已有 OpenCode V2 服务、已经能对话的模型，以及 Node.js 24.22 或 26 和 npm。在安装根目录执行：

```sh
git clone --branch v0.1.0-alpha.3 --depth 1 https://github.com/patslw/opencode-teamflow.git
cd opencode-teamflow
npm ci
npm run build
opencode service status
# 端口替换成上一步看到的本机 OpenCode 端口
npm run demo:prepare -- --endpoint http://127.0.0.1:49374
# 换成你实际可用的 provider/model
node scripts/install-collaboration.mjs .runtime/demo-project openai/gpt-6.1-terra
npm run demo:web
```

打开 **http://127.0.0.1:3180/**。需求讨论流程属于内置模板，不必导入文件。`demo:prepare` 只增量准备 `.runtime/`，不会修改全局 OpenCode 配置。要从局域网或不同开发机访问，见[网络配置](network.md)。

## 使用日常 TUI

```sh
npm run demo:tui -- local "$(pwd)/.runtime/demo-project"
```

在已有的顶层聊天输入 `/teamflow`，从「启动流程」选「先讨论，再实现」，这条聊天就是团队主入口。成员各用独立会话，不会把日常列表变成成员名单。TUI 和网页可以打开同一个团队。

## 单独设计流程

左侧 **设计工作流程** 是给想改协作规则的人用的。比如「验收前要请一位独立成员检查」。可以直接和设计者讨论，检查草稿里的变化，满意后再发布。讨论一个产品需求不必先设计流程。参见[团队协作与流程修改](workflows.md)。
