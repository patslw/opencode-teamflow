# 排错、数据与停止方式

| 现象 | 先做什么 |
|---|---|
| 网页打不开 | 使用启动日志中的完整 URL。默认本机是 HTTP；非回环是 HTTPS。`403` 时检查域名、端口、协议与 `--public-origin` 是否匹配；浏览器登录框使用独立网页口令。见[网络配置](network.md)。 |
| 无法连接后端或项目不匹配 | 对照 `opencode service status` 和 `.runtime/backends.json` 中的地址。检查项目的 `opencode.json` 是否指向当前安装的 `plugin` 绝对路径。移动过安装目录时要更新路径。修改映射后仅重启网页宿主。 |
| `401` 或 `429` | 看**实际运行该成员的服务**记录的 provider/model。401 是认证未通过，429 可能是额度或限流；主页面 HTTP 200 并不证明模型可用。在同一日常 OpenCode 配置里验证模型，不要把 API key 贴进模板、消息或 issue。 |
| TUI 找不到 Teamflow 菜单 | 从安装根目录用 `npm run demo:tui -- local <允许的绝对项目路径>` 启动；后端装了服务插件，不等于另一个 TUI 客户端已经加载了客户端插件。 |
| 浏览器断线时，按钮看似没完成 | 重连并读取当前状态；有未决请求时，先核对原请求 ID，只按原身份重试。不要用新名字再创建一个实例。 |
| 原生会话找不到 | 记录原 ID、后端和项目目录。不要用新 session 替代、直接编辑 SQLite 或把 `NotFound` 当作任务已结束。 |

**数据在哪里？** 新安装默认使用 `.runtime/demo-project/` 作为体验项目，Teamflow 业务状态在 `.runtime/backend-state/`；本地配置在 `.runtime/backends.json`。真实对话由原 OpenCode 服务保存。网页重启不会删除任务、会话或模型配置。

**如何停止？** 想停止继续派工，在实例里明确暂停。关闭网页标签不会暂停团队；在网页宿主终端按 `Ctrl+C` 只停止网页入口。不要为停网页而停掉日常 OpenCode。备份业务库时使用 SQLite 在线备份，勿只拷贝一个正在写入的主数据库文件。

**使用已有项目**：先在专用练习目录体验成功，再将目标项目的绝对路径加入本地配置的 `projects`，并在目标项目的 OpenCode 配置中**增量**加入插件声明，保留原插件和权限。可以对照 `.runtime/demo-project/opencode.json` 的生成结果；角色安装脚本故意只写本安装的 `.runtime/`，其它项目需自行检查并复制需要的角色和 Skill。

**使用其它开发机**：网页宿主可以连接管理员预先登记的端点。对 SSH-only 机器，在网页宿主建立 SSH 转发后再登记对应的回环地址和远端项目绝对路径。这个 alpha 不代管 SSH 登录；跨机器路径与断线行为仍需按实际环境验证。
