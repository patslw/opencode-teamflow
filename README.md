# Teamflow for OpenCode · 0.1.0-alpha.3

在 OpenCode 里带一个小团队做开发：你和协调者讨论需求，成员在各自的会话工作；在流程图上查看交付、找具体成员私聊，由你决定批准还是返工。**Alpha 是可操作的演示版本**。它复用你已有的 OpenCode 服务和模型认证，不需要再启动一套 OpenCode。

## 从哪里开始

- **第一次用**：在首页说一个还没想清楚的想法。负责人先提问，得到你的回答、提交方案；你点「同意方案，开始制作」之前不会安排开发。见[第一次团队对话](docs/guide/quickstart.md)。
- **多台服务器**：用 `npm run demo:web -- --host <本机局域网IP> --port 3180` 开启 HTTPS 网页；另见[配置远端后端和 SSH 跳板](docs/guide/network.md)。
- **想试协作和改流程**：见[成员、议题、流程设计与补丁](docs/guide/workflows.md)。
- **连不上或模型不回复**：见[排错、数据与停止方式](docs/guide/operations.md)。

| 入口 | 用途 |
|---|---|
| 浏览器 `http://127.0.0.1:3180` | 查看和编辑图、检查会话、交付证据和审批；比较并应用运行中的流程修改 |
| TUI → `Ctrl+P` → `Teamflow 流程` | 在终端启动流程、查看状态、打开具体成员或流程设计会话 |
| OpenCode 服务插件 | 保存实例、调度任务、核对批准者与产物版本；关闭网页不代表任务完成 |

**在日常 Sessions 里只找主入口。** 从已有顶层聊天启动时会沿用这条聊天；从网页启动会为实例创建一个主入口。成员、子成员和流程设计者使用独立的归档会话，可从 Teamflow 进入和私聊。父子关系登记在 Teamflow，子成员收尾不会通过原生父会话通知额外唤醒主模型。已有历史会话不会被批量改动。

`require-development` 从初步方案、用户确认进入产品 Demo，必须再次得到用户确认才允许进入正式开发；`bug-fix` 包括修复、独立检视和用户验收。可以从模板草稿发布新的不可变版本；已有实例不会随模板发布而自动升级。

## 环境与范围

Alpha 面向单用户 Linux、本机已配置好的 **OpenCode V2**、Node.js 24.22 或 26 和 npm。SDK 依赖锁定为 `2.3.0`；主服务使用过 `2.3.2`。模型由你的 OpenCode 提供，安装 Teamflow 不会获得额外额度或授权。

网页默认只监听回环地址。可显式绑定局域网地址；非回环入口使用 HTTPS 和独立网页口令。模型、文件及会话仍在所选后端，不随你的浏览器移动。在你自己的测试项目体验。本版本没有发布 npm 包；请使用 [GitHub Pre-release](https://github.com/patslw/opencode-teamflow/releases) 中的源码安装。

## 当前边界

- 个别早期会话的原生 ID 后来返回 `NotFound`，原因仍未确定。界面保留原 ID 和错误，不会新建会话冒充旧历史。
- 讨论结论不等于验收；「已投递」也不等于「成员已处理」。不确定的派工或消息需要核对，不应盲目重发。
- 专业成员通过检查后提出的新问题有业务层处理路径；此前真实模型验证在初始阶段遇到过 429/401，不能宣称所有否决时序都已端到端覆盖。
- 远端 OpenCode 可通过显式配置连接，但本机运行不依赖远端。未把本机演示当作真实远端验证。
